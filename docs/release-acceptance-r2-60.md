# R2-60 发布验收标准 v1

生效：2026-11-02，第七轮执行开始。依据：用户确认开始执行第七轮发布放行计划。此标准独立于 0.15.0 / PRD D1 冻结表；历史 HOLD 与原优化目标保留。

发布范围：最终候选的 K60U、PJZ110，实际可交付的60fps基础运行路径；120Hz增强结果另列。核心库不修改全局刷新率，宿主的60fps路径必须真实实现并记录实际系统授予模式及deadline。该策略尚待验证；若默认仍是120Hz且无可交付基础路径，则按真实默认模式验收，不以手工锁屏实验替代。

| 项目 | 发布要求 | 完整性条件 |
|---|---|---|
| CPU 帧 P95 | 普通与压力负载均 ≤16ms | 使用官方 FrameTiming；CPU ≤10ms 继续作为优化目标，CPU 达标同时还须满足实际呈现门槛。 |
| 普通负载正 overrun | ≤5% | 对系统分配的实际帧 deadline 计算；至少两次独立采集，每次均通过。 |
| 极限压力正 overrun | ≤10% | 同上；保留所有匹配帧、完整 trace 与分母。 |
| 静态轻载输入到呈现 P95 | ≤80ms | 每次 100/100 精确关联；最终执行两次独立采集。 |
| 压力输入到呈现 P95 | ≤100ms | 每次 100/100 精确关联；最终执行两次独立采集。 |
| 冷启动完整图表 TTFD P95 | ≤1500ms | 每台机 5 个有效冷启动样本；TTID 独立记录。 |
| 严格 warm TTFD P95 | ≤500ms | 每台机 5 个有效样本；每个预热/测量对保持同 PID，测量包含 Activity 重建与完整图表绘制。 |
| 100k 加载就绪 P95 | ≤2500ms | 每台机 5 个独立进程样本；首批可交互及全量就绪分开记录，全量就绪不是 TTFD。 |
| B-04 突发收敛 | ≤2s | 最后一个已接受操作至最终一致快照；不丢已接受数据或重排回调。 |
| B-05 释放 | 0 确定泄漏，retained ≤5MiB | 每台机最终 R8 包 30 次建销、同一 facade 100 次真实 setSymbol，实际 heap 与弱引用共同验证。 |
| B-06 热稳定 | 30 分钟无崩溃、ANR、无界增长 | 每台机留存进程、内存分类与温度时间序列；有增长须解释归因和边界。 |
| 正确性、布局与可访问性 | 无阻塞缺陷，关键用例全部通过 | 大字体横屏、图例首帧/缓存、可见命中区域、PNG、画线、数据切换和 TalkBack。 |

固定负载、最终矩阵与失败处理遵循[第七轮计划](alignment/release-readiness-round7-plan-2026-11-02.zh-CN.md)。各项数值分别在每台设备、每次完整采集中判定；跨模式和跨候选不混算。样本不足、原始trace缺失或必需项超限均不能GO。正式帧每负载两次，轻载/压力输入各两次且每次100/100精确关联，冷暖启动各5个有效样本，容量5个独立进程。

性能参数与门槛在观察新结果前锁定。后续若确需改变支持范围或标准，另发新版本、说明原因并完整复采；不改写本标准或旧结果。全部必需项通过后才形成技术GO，远程发布属于后续发布操作。
